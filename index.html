About Me

Welcome to my CS-499 Computer Science Capstone ePortfolio. This website showcases my work, technical skills, and improvements to projects completed during my degree.

My main artifact is Travlr Getaways, a full-stack application originally developed in CS-465. I am using the same project to demonstrate my progress in software design and engineering, algorithms and data structures, and databases.

Enhancement One: Software Design and Engineering

Enhancement implemented; final review and portfolio documentation ongoing.

My first enhancement focuses on improving the security of Travlr Getaways. I added JWT authentication, created an Angular login page, and protected administrative routes so users must be authenticated before accessing certain features. I also updated the back end to require authentication when adding, editing, or deleting trips.

This enhancement helped me better understand how front-end and back-end security work together. I also gained experience troubleshooting an existing application and using GitHub to manage my changes. The administrator login has been tested successfully, and I plan to make any additional improvements based on my instructor's feedback.

Enhancement Two: Algorithms and Data Structures

Enhancement implemented and tested; instructor review and final polishing pending.

For my second enhancement, I improved the trip listing page by adding searching, filtering, and sorting. Users can search for trips by name or resort, filter the results by a maximum price, and organize trips alphabetically or by price from lowest to highest.

I used TypeScript arrays and the filter() and sort() methods to process trip records. The search checks trip names and resorts without being case-sensitive. The price filter compares each trip's price against the amount entered, and the sorting step organizes the remaining results. These changes make it easier to find specific trips without having to look through every listing.

While testing this enhancement, I discovered that the MongoDB trips collection was empty, which prevented the application from displaying any trips. I imported the trip data using MongoDB Compass, tested the API again, and confirmed that the search, filtering, and sorting features worked with the restored records. The experience taught me to troubleshoot the front end, back end, and database together.

I originally considered pagination but deferred it so I could focus on making the three main features work correctly. Since the project currently uses a small number of trips, processing the results in Angular is reasonable. If the number of records grows, server-side searching, sorting, and pagination could be worthwhile improvements.
