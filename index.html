About Me

Welcome to my CS-499 Computer Science Capstone ePortfolio. I created this website to show how I have applied skills from my computer science coursework to improve an existing application. My goal is to demonstrate not only the finished features, but also how I planned, tested, and troubleshot those improvements.

The main artifact in my portfolio is Travlr Getaways, a full-stack travel application that I originally developed in CS-465. It uses Angular for the administrative interface, Node.js and Express for its API, and MongoDB for trip information. I selected this project because I could build on a working application while strengthening it in three areas: software design and engineering, algorithms and data structures, and databases.

As I work through the capstone, I am documenting my changes and reflecting on challenges I encountered. The source code is available through the GitHub links below, and I will continue updating this portfolio as the remaining enhancement is completed.

Enhancement One: Software Design and Engineering

Enhancement implemented; final review and portfolio documentation ongoing.

Purpose and improvements

My first enhancement focused on the security of the Travlr Getaways administrative interface. I wanted to make sure that administrative features were not simply available to anyone who opened the page. To address this, I added JSON Web Token (JWT) authentication, created an Angular login page, and protected administrative routes so users must sign in before accessing them.

I also updated the back end to check authentication when someone attempts to add, edit, or delete trip information. This was important because hiding buttons or pages in the front end alone would not be enough to secure the underlying API. The enhancement required me to think about how the Angular application, Express routes, and authentication process work together.

Testing and what I learned

I tested the administrator login and confirmed that the authentication request worked. While making the changes, I practiced troubleshooting, reviewing how different parts of the application communicate, and committing my progress through GitHub. I gained a better understanding of why security checks should be handled in both the user interface and the back end, rather than relying on only one layer.

This enhancement helped me apply software design and engineering concepts to a project I had already built. I plan to review any instructor feedback and make further improvements if needed.

Enhancement Two: Algorithms and Data Structures

Enhancement implemented and tested; instructor review and final polishing pending.

Purpose and improvements

For my second enhancement, I focused on improving how trip information is searched and organized. The original trip listing displayed records from the database but offered limited ways to narrow down the results. I wanted to make the page more useful, especially if additional trips were added in the future.

I added a search field that checks trip names and resorts, a maximum-price filter, and sorting options for alphabetical order or price from lowest to highest. These features work together, so someone can search for a particular resort, limit the results to trips within a budget, and sort the remaining matches.

Algorithms and data structures

The Angular component stores trips in a TypeScript array of Trip objects. I used the array filter() method to check the search text and price condition for each trip, then used sort() to order the matching results. For alphabetical sorting, I used localeCompare(); for prices, I compared the numeric values of the trip prices. The search also converts text to lowercase and trims the user's input so small differences in capitalization and spacing do not prevent a match.

Working with these operations helped me understand how data structures and algorithms affect the user experience. Filtering checks the records in the array, and sorting compares the remaining records to organize them. With a small dataset, processing this information in Angular is practical. For a much larger dataset, moving some of this work to the API or database could improve performance.

Testing, challenges, and reflection

One challenge came when the trip listing did not show any records. I checked the API and MongoDB and discovered that the trips collection was empty. I used MongoDB Compass to import the original trip data, then retested the page. After that, I confirmed that searching by a trip name, setting a maximum price, and changing the sort order produced the expected results.

I originally considered pagination, but I deferred it so I could concentrate on testing the search, filter, and sorting features. Since the application currently has only a few trip records, pagination was not necessary for this stage. The experience showed me how important it is to check the entire application—from the Angular interface to the database—when something does not work as expected.
